Why repro?

AI coding agents are powerful but unpredictable. When an agent makes a mistake — edits a file it shouldn't, loops on the same tool call, or takes too many API calls to do something simple — you want to:

  1. Capture the exact failure so you can study it later
  2. Replay it without spending money on API calls
  3. Assert that specific bad behaviors happened (or didn't)
  4. Commit the test so the failure is tracked and reviewable in PRs
  5. Run in CI without any API keys or network access

repro does all five. Think of it as a VCR for agent sessions — record once, replay forever.

Step-by-step guide
1
Initialize repro in your project

Navigate to your project's git repository and run:

$ repro init
repro: initialized .repro/ and REPRO.md

This creates .repro/ for trace data and REPRO.md as a human-readable manifest of known failures.

2
Record an agent run

Run your agent through repro's recording proxy. Everything after -- is the command repro will run.

$ repro record -- claude --print "fix the login bug"
repro: recording r-a1b2c3
repro: proxy listening on http://127.0.0.1:52431
repro: completed after 12 events
repro: saved r-a1b2c3

repro starts a local HTTP proxy, points the agent at it, and captures every request and response. The trace is saved in .repro/r-a1b2c3/.

3
Replay it to verify

Before saving, verify the recording replays correctly — no network, no API key.

$ repro run r-a1b2c3
repro: replaying r-a1b2c3 (12 events)
repro: mode: strict
repro: ✓ reproduced — 12 events, 0 API calls, 0 API keys

The agent runs against an isolated git worktree checked out to the same commit as the original run.

4
Save it as a named test

Promote the recording into your project's test manifest, optionally with assertions:

$ repro save r-a1b2c3 --title "agent edits generated files" \
  --assertion forbidden_path:src/gen/**
repro: saved r-a1b2c3 — "agent edits generated files"
repro: added to REPRO.md
5
Commit and push
$ git add REPRO.md .repro/
$ git commit -m "add repro: agent edits generated files"
$ git push

The trace, manifest, and assertions are all committed. Anyone who clones the repo can replay the failure.

6
Run all tests
$ repro test
repro: ✓ r-a1b2c3 — agent edits generated files
repro: ✓ 1 passed, ✗ 0 failed, ∅ 0 diverged

Add this to your CI pipeline. No API key needed.

Use case: catching an agent that edits generated files

You have a project with auto-generated API types in src/gen/. You ask Claude Code to fix a bug, and it edits a generated file instead of the source that generates it. Here's how to catch and prevent that.

Record the bad run:

$ repro record -- claude --print "fix the type error in getUserProfile"

Claude runs, and you notice it edited src/gen/api_types.ts — a file that should never be manually modified.

Save with a forbidden_path assertion:

$ repro save r-a1b2c3 --title "agent edits generated API types" \
  --assertion forbidden_path:src/gen/**

Replay to confirm the assertion catches it:

$ repro run r-a1b2c3
repro: ✓ reproduced — 12 events, 0 API calls, 0 API keys
repro: ✗ assertion: forbidden_path matched: src/gen/api_types.ts

The assertion fires. Commit it, add repro test to CI, and this failure is tracked permanently.

Other assertion examples:

# Fail if the agent makes more than 10 API calls
$ repro save r-xyz --title "agent loops" --assertion max_calls:10
# Fail if the same tool call repeats more than 3 times
$ repro save r-xyz --title "agent retries" --assertion no_repeat:3
# Run a custom check after replay
$ repro save r-xyz --title "output missing" --assertion command:"test -f output.txt"
How it works

repro uses a three-stage pipeline:

1. Record

Agent  ←→  repro proxy  ←→  Anthropic API
Proxy captures every request/response. Secrets redacted before disk.

2. Replay

Agent  ←→  repro proxy    ×  no network
Proxy serves recorded responses. Agent runs in an isolated git worktree.

3. Assert

Oracle-free assertions check what the agent did without needing a model to judge correctness. Assertions are evaluated against trace events and the filesystem state after replay.

Requests are matched by normalized content hash, not sequence number. Normalization strips volatile fields (timestamps, cache hints, model name, system prompt) so minor environmental differences don't cause false mismatches.

Assertions

Attach assertions when saving a recording. They are checked on every repro run and repro test.

TypeWhat it checks
forbidden_path:<glob>Fails if any tool call touches a matching path
no_repeat:<n>Fails if the same tool call (name + args) repeats > n times
max_calls:<n>Fails if total model API calls exceed n
command:<cmd>Runs a shell command in the worktree after replay; non-zero = failure
Replay modes

Strict (default for repro test): Requests are matched by normalized content hash. If the agent sends a request that doesn't match any recorded hash, replay aborts and reports which message diverged.

Lenient (--lenient): On a hash miss, falls back to positional matching. Warns on every fallback. Useful during development when you expect minor differences.

Recording options

Control how the agent is configured during recording. These flags go before the -- separator.

# Specify which model to use
$ repro record --model claude-sonnet-4 -- claude --print "fix the bug"
# Use your claude.ai subscription (no API key)
$ repro record --auth plan -- claude --print "fix the bug"
# Use API credits (requires ANTHROPIC_API_KEY)
$ repro record --auth credits -- claude --print "fix the bug"
FlagDescription
--model <name>Passed to the agent CLI and stored in trace metadata
--auth planUses claude.ai subscription; removes API key from agent's environment
--auth creditsUses API key auth; requires ANTHROPIC_API_KEY to be set
CI setup

No API key needed. The agent binary must be available on the runner.

# .github/workflows/repro.yml
name: Repro Tests
on: [push, pull_request]
jobs:
  repro-test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 22, cache: npm }
      - run: npm ci
      - run: npm install -g @anthropic-ai/claude-code
      - run: npx repro test

repro test exits 0 if all replays pass, 1 if any fail or diverge.

Redaction & security

Secrets are redacted at capture time, before anything touches disk:

  • Environment variables — non-standard values replaced with [[redacted:env:<hash>]]
  • Known patterns — API keys (sk-ant-*, ghp_*, AKIA*), JWTs, PEM blocks
  • Headers — Authorization and x-api-key stripped
  • File paths — content from .env*, *.pem, *.key, **/secrets/** redacted

Common non-secret env vars (PWD, HOME, PATH, etc.) are excluded from redaction — redacting them corrupts file paths and breaks replay.

Minimization

When you have a failing trace, find the minimum inputs needed to reproduce it:

$ repro minimize r-abc123 --inputs context,files,tools --budget 5.00
repro: minimizing 14 inputs (budget: $5.00)
repro: minimize result:
  original inputs: 14
  minimal inputs: 3
  reproduction rate: 100%
  spend: $1.24
This costs money. Minimization makes real API calls to test each candidate. The --budget flag caps your spend. The output reports a "minimal reproducing set" — never "cause."
FlagDefaultDescription
--budget <n>requiredMaximum spend in dollars
--inputs <types>context,files,toolsWhich input types to try removing
--k <n>3Samples per candidate
--m <n>2Minimum successes to accept
